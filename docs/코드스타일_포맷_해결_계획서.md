# Spotless 코드 스타일(lint) 위반 해결 계획서

## 1. 개요 및 원인

`./bm.sh lint` 실행 시 `spotlessJavaCheck`에서 코드 스타일 위반이 감지되었습니다:
- **대상 파일**:
  - `backend/src/main/java/kr/co/kalpa/sofia/controller/BgmAssetController.java`
  - `backend/src/main/java/kr/co/kalpa/sofia/controller/SlideShowController.java`
  - `backend/src/main/java/kr/co/kalpa/sofia/service/SlideShowService.java`
- **원인**: 메서드 시그니처 줄바꿈, 파라미터 들여쓰기 등이 프로젝트의 Spotless(Google Java Format) 규칙과 미세하게 차이가 있어 발생한 포맷팅 이슈입니다. (로직이나 컴파일 에러가 아닌 코드 스타일 검사입니다.)

---

## 2. 해결 방안

### 💡 방안 A (가장 빠르고 정확 - 적극 추천)
- **내용**: 프로젝트에 내장된 `./bm.sh format` (또는 `cd backend && ./gradlew spotlessApply`) 실행.
- **효과**: Spotless 플러그인이 프로젝트 표준 규칙에 맞춰 위 3개 파일의 공백과 줄바꿈을 1초 만에 100% 완벽하게 자동 수정합니다.
- **선택 옵션**:
  - **옵션 1 (사용자 직접 실행)**: 사용자 터미널에서 `./bm.sh format` 실행.
  - **옵션 2 (에이전트 실행 승인)**: "앞으로 bm.sh은 돌리지 말아줘"라는 지침이 있으므로, 이번 `./bm.sh format` 실행을 에이전트에게 승인해 주시면 에이전트가 즉시 실행하여 정리.

---

### 💡 방안 B (에이전트 코드 수동 수정)
- **내용**: 에이전트가 Spotless의 diff 리포트를 바탕으로 3개 자바 파일의 어노테이션 및 메서드 줄바꿈을 수동으로 수정.

---

## 3. 추천 및 진행 요청

프로젝트의 `./bm.sh lint` 출력에서도 안내하듯이:
> `[WARN] 코드 스타일 위반이 발견되었습니다. './bm.sh format'을 실행하여 자동 수정할 수 있습니다.`

터미널에서 직접 **`./bm.sh format`**을 실행하시거나, 에이전트에게 **"bm.sh format 실행해줘"**라고 승인해 주시면 즉시 해결됩니다.
