# PDF 만들기 기능 개편 및 설계 분석 보고서

## 1. 개요 및 배경

최근 개편된 **Merge(이미지 병합)** 기능은 *"합쳐진 이미지가 사각형 형태를 채우고, 하얀색 바탕(여백)이 될 수 있으면 없어야 한다"*는 원칙 하에, 사용자가 지정한 옵션(테두리, Row당 갯수, 너비, X/Y 간격)에 맞춰 캔버스 크기를 동적으로 밀착(Tight-fit)시키는 방식으로 전면 재작성되었습니다.

본 문서는 **"PDF 만들기 기능도 Merge와 유사하게 개편이 가능한가? 아니면 어떤 제약 사항이 존재하는가?"**라는 질문에 대한 기술적 분석과, 이를 바탕으로 한 구체적인 PDF 기능 개편 계획을 기술합니다.

---

## 2. Merge vs PDF: 유사점 및 핵심 제약 사항 비교

### 2.1 유사하게 구현 가능한 요소 (공통점)

| 항목 | Merge 기능 | PDF 만들기 적용 가능 여부 | 구현 방식 |
| :--- | :--- | :---: | :--- |
| **테두리선 (Border)** | 없음/적용, 두께(1~4px), 색상 | **완전 동일하게 가능** | PDFBox의 `setStrokingColor` + `addRect` + `stroke`로 고품질 벡터 테두리 렌더링 |
| **Row당 갯수 / 열 배치** | 1, 2, 3, 4개 선택 | **완전 동일하게 가능** | 페이지 내에서 1열, 2열, 3열, 4열 그리드 분할 |
| **홀수 개수 채움 로직** | 마지막 1장은 행 전체 너비로 확장 | **완전 동일하게 가능** | 해당 페이지의 마지막 남은 이미지가 1장이면 행 전체 폭을 차지하도록 확장 배치 |
| **이미지 간격 (Gap)** | X축/Y축 간격 (0~5px + 직접입력) | **완전 동일하게 가능** | 셀과 셀 사이의 간격(Gap X/Y)을 pt 단위로 적용 |
| **옵션 설정 팝업 UI** | 모달에서 직관적 설정 | **완전 동일하게 가능** | 전용 `PdfOptionsModal`을 통해 일관된 UX 제공 |

---

### 2.2 PDF 고유의 물리적 / 기술적 제약 사항 (차이점)

Merge는 **단일 래스터 이미지(JPG)**를 생성하는 반면, PDF는 **인쇄 및 문서 표준 규격**을 따르기 때문에 다음과 같은 본질적인 제약 사항이 있습니다:

#### ⚠️ 제약 1: 고정된 페이지 규격 (Fixed Page Size)과 세로 여백
- **Merge의 경우**:
  - 이미지가 몇 장이든 행들을 세로로 쌓은 후, **실제 쌓인 높이의 합에 딱 맞게 캔버스 높이를 동적으로 결정(Crop)**하므로 하단에 하얀 여백이 전혀 생기지 않습니다.
- **PDF의 제약**:
  - PDF는 기본적으로 **A4(595.28 × 841.89 pt)** 등 규격화된 "용지 크기"가 고정되어 있습니다.
  - 예를 들어, A4 용지 한 페이지에 3장의 사진을 [2장 / 1장] 구조로 넣었을 때, 사진 원본의 비율을 유지하면서 가로 폭을 채우더라도, **A4 종이의 고정된 세로 높이(841.89pt)를 딱 채우지 못하면 종이 아래쪽에 빈 공간(여백)이 필연적으로 발생**합니다.
  - 종이 자체를 자르지 않는 한, **[종이의 고정 비율] ≠ [사진들의 합산 비율]** 불일치 문제는 수학적으로 불가피합니다.

#### ⚠️ 제약 2: 다중 페이지 분할 (Pagination)
- Merge는 50장이 선택되어도 1장의 초장축 세로 이미지로 이어붙일 수 있지만, PDF는 1페이지를 채우면 **다음 페이지(Page 2, Page 3...)로 넘어가야 합니다.**
- 따라서 "Row당 갯수"뿐만 아니라 **"페이지당 이미지 갯수(Images per Page)"** 또는 **"페이지 넘김 기준"**이 명확해야 합니다.

#### ⚠️ 제약 3: 실제 인쇄(Print) 불가 영역 (Hardware Margins)
- 이미지는 화면 픽셀 기준으로 0px 완전 외곽 채움이 자연스럽지만, PDF는 실제 A4 용지로 출력(인쇄)하는 경우가 많습니다.
- 일반적인 가정용/사무용 프린터는 종이 끝 3~5mm(약 10~15pt) 영역에 잉크를 분사하지 못하는 **하드웨어 인쇄 불가 영역**이 있습니다.
- 따라서 여백을 무조건 0으로 만들면 인쇄 시 테두리나 사진 일부가 잘려나갈 수 있어, **"인쇄용 기본 여백(Margin)"** 옵션이 필요합니다.

#### ⚠️ 제약 4: 좌표계 및 단위 (Points & Inverted Y-Axis)
- 이미지는 좌상단 (0,0), 가로 X 증가, 세로 Y 증가 (픽셀 단위).
- PDF(PDFBox)는 **좌하단 (0,0)**, 위로 갈수록 Y 증가 (**포인트 단위: 1pt = 1/72인치**).
- 따라서 셀 좌표 및 렌더링 시 상하 반전 계산(`pageHeight - y - h`)을 정밀하게 처리해야 합니다.

## 3. PDF의 "하얀 여백 최소화" 해결 전략 비교

PDF에서도 사용자의 핵심 요구사항인 *"가능한 한 사각형 형태를 채우고 하얀 여백을 줄인다"*를 달성하기 위해 3가지 접근 방식을 제안합니다:

```
[방식 A: 스마트 맞춤 (Smart Fit)]   [방식 B: 꽉 채움 크롭 (Cover Crop)]  [방식 C: 가변 용지 (Custom Page)]
┌────────────────────────┐         ┌────────────────────────┐         ┌────────────────────────┐
│ ┌──────────┐┌──────────┐ │         │ ┌──────────┬──────────┐ │         │ ┌──────────┐┌──────────┐ │
│ │  사진 1  ││  사진 2  │ │         │ │  사진 1  │  사진 2  │ │         │ │  사진 1  ││  사진 2  │ │
│ └──────────┘└──────────┘ │         │ ├──────────┴──────────┤ │         │ ├──────────┴──────────┤ │
│ ┌──────────────────────┐ │         │ │       사진 3        │ │         │ │       사진 3        │ │
│ │        사진 3        │ │         │ │    (위아래 일부잘림)  │ │         │ └─────────────────────┘ │
│ └──────────────────────┘ │         │ └─────────────────────┘ │         └────────────────────────┘
│ (용지 하단 여백 일부 존재)│         │ (하얀 여백 0%, 사진 잘림)│         (내용물에 맞춘 비규격 용지)
└────────────────────────┘         └────────────────────────┘
```

### 방식 A: 스마트 그리드 맞춤 (Smart Contain) - [권장 기본값]
- **동작**:
  - 사진의 원본 비율(Aspect Ratio)을 100% 보존하며 자르지 않음.
  - 홀수 개수일 경우 마지막 이미지를 행 전체 폭으로 확장하여 가로 방향 빈 공간을 완전히 없앰.
  - 페이지 방향을 이미지들의 형태에 맞춰 **자동(Auto - 세로/가로형 전환)**으로 결정하여 상하 여백을 최소화.
- **장점**: 원본 사진 손상이 없고 표준 A4 규격 유지.

### 방식 B: 꽉 채움 크롭 (Full Bleed Cover & Crop) - [선택 옵션]
- **동작**:
  - 지정된 셀 영역의 가로와 세로를 100% 꽉 채우며, 비율을 유지하되 영역을 벗어나는 상하 또는 좌우 일부를 크롭(Center-crop).
- **장점**: 종이 내에 하얀 여백이 단 1%도 남지 않고 잡지/화보처럼 꽉 참.
- **단점**: 사진의 가장자리가 일부 잘려나감.

### 방식 C: 내용물 맞춤 가변 용지 (Tight Page Size) - [선택 옵션]
- **동작**:
  - A4 규격을 고집하지 않고, 배치된 이미지들의 실제 크기 합산값으로 PDF의 `MediaBox` 크기 자체를 동적으로 생성.
- **장점**: Merge와 100% 동일하게 하얀 여백 없는 완벽한 사각형 PDF 생성.
- **단점**: 일반 A4 프린터로 1:1 출력 시 용지 비율과 맞지 않을 수 있음 (PDF 뷰어 화면 보기에는 최적).

## 4. 개편 계획 및 상세 UI / 기능 스펙

### 4.1 프론트엔드 모달 (`PdfOptionsModal.tsx`)

Merge 모달과 일관된 디자인 시스템(Tailwind + shadcn)으로 전면 리뉴얼:

1. **테두리선 (Border)**:
   - 없음 / 테두리 적용 (토글)
   - 두께: `1pt`, `2pt`, `3pt`, `4pt`
   - 색깔: 기본 블랙(`#000000`), 프리셋 6종 + 컬러 피커 + HEX 입력 + 실시간 미리보기
2. **페이지당 이미지 배치 (Layout)**:
   - `1장 (전체 채움)`
   - `2장 (1행 2장 or 2행 1장)`
   - `3장 (1행 2장 + 2행 1장 꽉 채움)` ⭐ 신규 추가
   - `4장 (2 × 2 격자)`
   - `6장 (2 × 3 격자)`
3. **용지 맞춤 모드 (Fit Mode)**:
   - `비율 유지 (사진 전체 보기)`: 여백 최소화하되 사진 자름 없음
   - `종이 꽉 채우기 (여백 없이 채움)`: 사진 중앙 기준으로 빈틈없이 채움
   - `내용물 맞춤 용지 (가변 크기)`: 여백 없이 이미지 크기에 맞춘 PDF
4. **페이지 방향 (Orientation)**:
   - `자동 (Auto)`: 첫 이미지 비율에 따라 페이지별 세로/가로 자동 판단
   - `세로 (Portrait)`: A4 세로 고정
   - `가로 (Landscape)`: A4 가로 고정
5. **페이지 외곽 여백 (Margin)**:
   - `없음 (0pt)`
   - `좁게 (10pt / 약 3.5mm)`
   - `보통 (20pt / 약 7mm)`
   - `인쇄용 (36pt / 약 12.7mm)`
6. **이미지 간격 (Gap)**:
   - `없음 (0pt)`, `2pt`, `5pt`, `10pt` + 직접입력

---

### 4.2 백엔드 (`ImageService.java` & `ImageController.java`)

1. **요청 DTO 확장 (`ImageExportRequest`)**:
   - `border`, `borderWidth`, `borderColor`
   - `pdfLayout`: "1", "2", "3", "4", "6"
   - `fitMode`: "contain", "cover", "tight"
   - `orientation`: "auto", "portrait", "landscape"
   - `pageMargin`: 여백 (pt)
   - `gap`: 이미지 간격 (pt)

2. **PDFBox 렌더링 파이프라인 고도화**:
   - **벡터 테두리**: 비트맵에 그리는 것이 아니라 PDFBox의 벡터 패스(`addRect`, `stroke`)로 테두리를 그려 확대해도 깨지지 않는 초고화질 테두리 구현.
   - **스마트 배치 알고리즘**:
     - 3장 배치 시: 1행에 2장, 2행에 1장(가로 100% 폭)으로 자동 레이아웃.
     - `cover` 모드 선택 시 중앙 기준 크롭 렌더링.
   - **메모리 최적화**: 임시 파일 생성을 지양하고 `JPEGFactory.createFromStream`을 스트리밍 방식으로 연결하여 대용량 PDF 변환 속도 대폭 개선.

## 5. 결론 및 요약

- **결론**: **PDF 만들기도 Merge와 매우 유사하게, 그리고 훨씬 강력하게 구현 가능합니다.**
- **핵심 차이**: 고정된 종이 규격(A4)으로 인한 세로 여백 문제는 **"용지 맞춤 모드(비율 유지 vs 꽉 채움 크롭 vs 내용물 맞춤 용지)"** 옵션을 제공함으로써 완벽하게 해결할 수 있습니다.
- **다음 단계**: 본 계획서 검토 후 동의해 주시면, `PdfOptionsModal` 개발 및 백엔드 `exportAsPdf` 리팩토링 작업을 신속하게 진행할 수 있습니다.
