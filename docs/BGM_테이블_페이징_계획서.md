# BGM 자산 관리 Table UI 전환 및 페이징/검색/정렬 기능 구현 계획서

## 1. 현재 상태 및 질문에 대한 답변

- **페이징 적용 여부**: **현재 페이징 처리가 되어 있지 않습니다.**
  - 현재 `BgmAssetManager.tsx`는 백엔드(`GET /api/assets/bgm`)에서 전체 목록을 불러와 단순 세로 구분선 리스트(`divide-y divide-gray-100`)로 한 번에 나열하고 있습니다.
  - 음원 개수가 20~30개 이상만 되어도 페이지가 길어져 스크롤을 많이 해야 하는 불편이 있습니다.
- **Table UI 도입 제안**: **매우 적절하고 추천합니다.**
  - 최근 `SettingsPage` 폭을 브라우저의 80%(`w-[80%] min-w-[320px]`)로 확장했기 때문에, 넓은 가로폭을 활용한 **Table(표) 레이아웃**이 정보 밀도와 시각적 안정감 면에서 훨씬 우수합니다.
  - [재생 버튼] | [파일명] | [파일 크기] | [등록일시] | [삭제] 컬럼 구조로 한눈에 비교/탐색하기 좋아집니다.

## 2. 세부 UI/UX 구성 계획

```
+----------------------------------------------------------------------------------------------------+
| [배경음악(BGM) 자산 관리]  [ 38곡 ]                              [🔍 파일명 검색...]  [+ 음원 업로드] |
| 드래그 앤 드롭 업로드 영역 (축소/접이식 또는 상단 콤팩트 카드)                                              |
+----------------------------------------------------------------------------------------------------+
| [재생] | 파일명 (오름/내림차순 정렬)        | 파일 크기 (정렬) | 등록일시 (정렬)    | 관리              |
+----------------------------------------------------------------------------------------------------+
| [▶]   | acoustic_guitar_warm.mp3          | 4.8 MB           | 2026.09.07 14:20   | [🗑️]             |
| [⏸]   | upbeat_travel_vlog.mp3 (재생 중~)  | 5.2 MB           | 2026.09.07 13:45   | [🗑️]             |
| [▶]   | piano_romance_soft.mp3            | 3.1 MB           | 2026.09.06 18:10   | [🗑️]             |
+----------------------------------------------------------------------------------------------------+
| [총 38개 중 1 - 10번째]              [페이지당: 10개 ▼]          [◀] [1] [2] [3] [4] [▶]          |
+----------------------------------------------------------------------------------------------------+
```

### 1) 툴바 및 검색 필터 (Top Toolbar)
- **실시간 검색창**: 파일명(`filename`)을 즉시 검색할 수 있는 입력창 제공 (검색어 입력 시 즉시 필터링 및 1클릭 리셋 `✕` 버튼).
- **카운트 표시**: 전체 곡 수 및 필터링된 결과 개수 표시 (예: "검색결과: 5 / 총 38곡").
- **업로드 액션**: 기존 파일 선택 버튼 및 드래그 앤 드롭 영역을 콤팩트하게 배치.

### 2) 데이터 테이블 (Table Structure)
- **헤더 클릭 정렬**:
  - `파일명` (가나다/ABC 순)
  - `파일 크기` (용량 크기순)
  - `등록일시` (최신순 / 오래된순)
  - 정렬 상태 표시 아이콘 (`ArrowUpDown`, `ArrowUp`, `ArrowDown`).
- **테이블 행(Row)**:
  - **재생 컨트롤**: 원형 버튼 클릭 시 즉시 재생/정지. 재생 중인 행은 은은한 블루 배경(`bg-blue-50/60`)과 애니메이션 사운드 아이콘 표시.
  - **파일명**: 강조된 파일명과 확장자 표시.
  - **크기**: 읽기 쉬운 포맷 (`formattedSize`).
  - **등록일시**: 포맷팅된 날짜 시간 (`YYYY.MM.DD HH:mm`).
  - **삭제**: 우측 휴지통 버튼으로 삭제 (삭제 시 안전 확인 대화상자).
  - 마우스 오버 시 행 호버 효과(`hover:bg-gray-50/80`).

### 3) 페이징 컨트롤 (Pagination Footer)
- **페이지 크기 선택**: `10개씩`, `20개씩`, `50개씩` 보기 드롭다운.
- **페이지 번호 이동**: 이전/다음 버튼(`ChevronLeft`, `ChevronRight`) 및 1, 2, 3... 페이지 번호 버튼.
- **데이터 범위 표시**: "총 N개 중 A - B번째".
- 검색 조건이나 페이지 크기 변경 시 1페이지로 자동 이동.

### 4) 클라이언트 사이드 vs 서버 사이드
- BGM 음원 자산은 일반적으로 수십~수백 개 수준이므로, 브라우저 메모리 내에서 `useMemo` 기반의 클라이언트 사이드 정렬·검색·페이징을 적용합니다.
- **장점**:
  - 키보드로 검색어를 치는 순간 지연 시간(0ms) 없이 즉시 반응.
  - 추가적인 백엔드 API 변경이나 DB 쿼리 오버헤드가 없음.
  - 페이지 전환 시 깜빡임 없이 즉각 반응.

## 4. 검증 계획

1. **빌드 및 린트 검증**:
   - `./fm.sh lint`: ESLint 문법 및 스타일 검사 (에러 0건).
   - `./fm.sh build`: Vite 빌드 정상 성공 및 `backend/src/main/resources/static` 배포 확인.
2. **기능 검증**:
   - 파일명 검색어 입력 시 실시간 필터링 동작 확인.
   - 컬럼 헤더(파일명, 크기, 등록일시) 클릭 시 오름차순/내림차순 정렬 동작 확인.
   - 10개/20개/50개 단위 페이징 전환 및 페이지 번호 이동 확인.
   - 테이블 행 내 재생/일시정지 정상 작동 및 삭제 기능 확인.
   - 음원 업로드/삭제 후 목록 자동 갱신 및 페이징 상태 보정 확인.
